# 电子秤收银系统 — 功能分析与实施计划

> 本文档由对话式需求讨论确认生成，作为开发需求基线。

## 摘要

面向**超市/生鲜区**的电子秤收银系统，**桌面 + Web 混合**架构：桌面端（Tauri+Rust+Vue3）负责收银终端的称重、收银、打印；Web 后台（Vue3 + Python FastAPI）负责商品、库存、会员、促销、报表管理。SQLite 起步、预留 PostgreSQL 扩展，单店起步预留多店字段。

## 一、已确认功能清单

### 收银终端（桌面端）

| 模块 | 确认的功能 |
|---|---|
| **称重** | 通用串口方案读取重量（秤型未定，协议可插拔，后期适配实际秤）；模拟秤调试模式；实时重量显示；去皮/置零；稳定判定；**默认自动确认计价、可配置手动**；标准品（按件）不走称重；秤故障可手动输重量 |
| **收银** | 扫码枪/搜索/分类点选录入商品；购物车增删改；称重计价（重量×单价）、按件计价；**快捷键 + 常用商品快捷按钮**；**挂单/取单（多笔）**；单项/整单折扣 |
| **支付** | 现金（找零+开钱箱）；微信/支付宝**先扫码记账**（预留官方接口）；会员储值扣款；组合支付 |
| **退款** | **收银员可退本人当班订单**，整单退+单项退 |
| **打印** | 价格标签**自动打印+补打**（含商品名/重量/单价/金额/日期/保质期/称重条码，58mm）；小票标准内容（门店抬头/流水号/明细/合计/支付/收银员/时间/积分/广告语，58/80mm） |
| **交接班** | 登录接班、**交班打印本班汇总小票**（订单数/销售额/各支付方式金额） |

### 后台管理（Web）

| 模块 | 确认的功能 |
|---|---|
| **商品** | 档案（条码/名称/拼音码/分类/计价方式/单位/零售价/会员价/进价/保质期/库存）；两级分类；**Excel 导入导出、批量改价**；启停用；变更留痕；增量下发收银端 |
| **库存** | **完整库存**：入库、销售自动扣减（称重按重量/按件按数量）、盘点（支持接秤称重盘点）、生鲜报损、库存预警、进销存流水 |
| **会员** | 手机号建档；等级（决定折扣）；**会员价**；**积分制**（消费积分、积分抵扣）；**储值卡**（充值/赠送/扣款/退款）；变动流水 |
| **促销** | **限时特价**（带时间段）、**折扣**（整单/分类/商品/会员）、**满减满赠**；收银端规则引擎自动生效；促销订单可查 |
| **报表** | **销售日报/月报**、**商品销售排行**（金额/重量）、**时段分析**、**毛利分析**（进价-销售额）、**会员分析**（消费/储值/积分）；全部可导出 Excel，图表展示 |
| **系统** | 角色权限（管理员/店长/收银员）；操作日志；交接班；系统参数（门店/秤/打印机/积分储值规则）；数据备份；离线收银+自动同步 |

### 数据同步

- 下行：商品/价格/促销/会员增量下发收银端（本地 SQLite 缓存，离线可收银）；
- 上行：订单/库存变动/交接班上传服务端；断网自动重试；商品价格以 Web 为准。

## 二、关键决策

| 项 | 决策 |
|---|---|
| 平台 | 桌面（Tauri+Rust+Vue3）+ Web 后台（Vue3）+ API（Python FastAPI） |
| 数据库 | 桌面 SQLite 本地；服务端 SQLite 起步（SQLAlchemy+Alembic 可切换 PostgreSQL） |
| 多店 | 单店起步，预留店 ID 字段 |
| 秤 | 通用串口文本协议 + 模拟秤调试，协议适配器可插拔 |
| 支付 | 扫码记账（预留 PaymentProvider 接口） |
| 界面 | 全中文，POS 触屏大字号；Element Plus 共用 |

## 三、实施路线

| 阶段 | 内容 | 产出 |
|---|---|---|
| S1 骨架 | Tauri / FastAPI / Vue 三端初始化 + 数据库建表 | 三端可运行空壳 |
| S2 商品后台 | 商品/分类 CRUD + Excel 导入导出 + API + 收银端同步 | 商品可录可下发 |
| S3 收银核心 | 称重模块（可插拔+模拟秤）、POS 界面、购物车、结算、本地订单、上传 | 称重计价收银闭环 |
| S4 打印 | 标签打印（含重量条码）、小票打印 | 结算自动出票出标签 |
| S5 业务增强 | 会员（价/积分/储值）、促销规则引擎、库存 | 业务功能齐全 |
| S6 报表管理 | 5 类报表+导出、权限、交接班、日志、备份、系统参数 | 可营业 |

> 遵循用户规则：一个类一个文件、中文注释；每小处更改提交、需求完成验证后推送远端。

## 四、验证

- 每阶段构建运行自测；S3 起用模拟秤验证称重→计价→收银→打标→上传→报表全链路；Rust 侧协议/金额单测，Python 侧 pytest。
